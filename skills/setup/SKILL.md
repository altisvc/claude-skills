# Skill: Setup

> Interactive configuration wizard that generates `.claude/user.yaml` — the config file all other skills read from. Run once on first install, re-run to update.

---

## Skill Metadata

```yaml
id: setup
trigger: /setup
context: orchestrated
returns: user_yaml
required: false
```

---

## Purpose

Skills like checkin, meeting-sync, and audit reference Slack channels, Trello boards, file paths, and other values that vary by user or machine. Without a config file, every skill ships with Altis-specific hardcoded values that break on anyone else's setup.

`/setup` generates `.claude/user.yaml` — a single config file that skills read at runtime. It ships org-level defaults (shared Slack channels, Trello boards, GitHub repos) and asks only for values that vary per person.

---

## Invocation

```
/setup
```

No arguments. Re-run anytime to update config.

---

## Stage 1: Identity & Org

Ask the user:

```
Let's set up your Claude Code environment. First, a few basics:

1. What's your name?
2. What's your email? (used for Trello card attribution, git commits)
3. Are you on the Altis team or Primary team?
4. What's your role? (CEO, research, engineering, operations, other)
```

Store responses internally.

**Org determines defaults:** Altis and Primary have different Slack workspaces, channel sets, and Trello boards. The org answer loads the right defaults — the user only needs to confirm or override, not enter IDs manually.

| Setting | Altis | Primary |
|---------|-------|---------|
| Slack workspace | Altis (MCP connected) | Primary.vc (T03KQRA9L, browser only) |
| Slack channels | 20 channels (see Stage 4) | #investmentteam, #altis-primary-gtm, DMs |
| Trello | Staging + Pipeline boards | None (unless configured) |
| GitHub org | altisvc | N/A |
| Internal domains | altis.vc, primary.vc, deck.support | primary.vc |

Primary team members get a lighter config — fewer integrations, no Trello, no GTM agent paths.

## Stage 2: Project Directory

Detect automatically:

```bash
pwd
```

Confirm with the user:

```
Your project directory looks like it's at [detected path]. Is that right, or should I use a different location?
```

---

## Stage 3: Integration Detection

Probe for available integrations silently, then report what's found:

**Slack:** Try a lightweight MCP call (e.g., list channels with limit 1). If it works, Slack is connected.

**Trello:** Check if env vars are set:
```bash
echo "${TRELLO_API_KEY:+set}" "${TRELLO_TOKEN:+set}" "${TRELLO_BOARD_ID:+set}"
```

**Granola:** Check if MCP tool `mcp__granola__find_recent_meetings` is available.

**Google Workspace (gws):**
```bash
which gws 2>/dev/null && echo "installed" || echo "not found"
```

**Thoughtful.app:**
```bash
echo "${THOUGHTFUL_API_KEY:+set}"
```

**GitHub SSH:**
```bash
ssh -T git@github.com 2>&1 | head -1
```

Report to user:

```
Here's what I found on your machine:

  Slack:        ✓ Connected (MCP)
  Trello:       ✓ API key + token set
  Granola:      ✓ MCP available
  Google (gws): ✗ Not installed
  Thoughtful:   ✗ API key not set
  GitHub SSH:   ✓ Authenticated as [username]

Skills that need missing integrations will still install but those features won't work until configured.
```

## Stage 4: Role-Based Defaults

Based on the user's role, pre-select which Slack channels to monitor and which skills to recommend:

**CEO / Operations:**
- All 20 Slack channels (full sweep)
- Recommended: checkin, wrap, meeting-sync, audit, consult-advisor, week-in-review, wiki-lint
- All Trello integration

**Research:**
- Research channels (#researchteam, #researchsignals, sector channels, #research-coverage, #research-enablement, #research-efficiencies, #research-recruiting, #research-expert-sourcing)
- Plus: #all-altis, #primary-altis
- Recommended: wrap, meeting-sync, consult-advisor (research advisors)

**Engineering:**
- #aibuild, #aitis, #all-altis, #altisxthoughtful
- Recommended: wrap, wiki-lint

**Other:**
- #all-altis, #primary-altis
- Recommended: wrap, consult-advisor

Ask user to confirm or customize the channel list and skill recommendations.

## Stage 6: Optional Skill Install

If the user says yes, provide the install prompts for their selected skills (from the marketplace registry). Do NOT auto-install — let them choose which ones to start with.

---

## Re-run Behavior

If `.claude/user.yaml` already exists when `/setup` is invoked:

1. Read the existing config
2. Show current settings
3. Ask: "Want to update anything, or run a fresh setup?"
4. If updating, only ask about the changed sections
5. Preserve `installed_skills` list

---

## What This Does NOT Do

- Does not templatize existing SKILL.md files (that's a separate migration)
- Does not install skills automatically
- Does not configure external services (Trello auth, Slack app install, etc.)
- Does not modify shell profiles (~/.zshrc)

The setup wizard generates the config. Skills read it. Migration of skills to read from user.yaml is a separate effort tracked in the marketplace roadmap.
